## 3. 이번 검증에서 발견한 구현 결함

### 3.1 KIS 지수 분봉 시간 파라미터

KIS 지수 분봉은 `FID_INPUT_HOUR_1="60"`으로 호출했을 때 102행을 반환했다. 기존 `market_strength.py`는 이 자리에 `HHMMSS` 시각을 전달하고 있어 빈 응답 또는 환경별 오작동 가능성이 있다.

처리 방침:

- Phase 2에서 기존 파일의 사용자 변경과 충돌 여부를 먼저 확인한다.
- 지수 분봉 호출 계약을 공통 클라이언트로 이동한다.
- `999999`, `888888` 같은 특수 시각 행을 일반 분봉과 분리한다.

### 3.2 토큰 반복 발급

초기 프로브는 항목마다 KIS 토큰을 새로 발급해 첫 호출 이후 403을 받았다.

수정 완료:

- 한 프로세스에서 KIS·키움 클라이언트를 공유한다.
- KIS 토큰 캐시를 재사용한다.
- 토큰은 보고서와 오류 메시지에 저장하지 않는다.

### 3.3 휴장일 데이터 신선도

2026-08-01 토요일 호출에서 샘플 기준일이 원천별로 일치하지 않았다.

- KIS 종목 분봉 샘플: `20260730`
- KIS 지수 분봉 샘플: `20260731`
- KIS 투자자 수급 첫 행: `20260731`
- KIS 선물 분봉 샘플: `20260730`

이 값만으로 API 오류라고 단정하지 않는다. 다만 “가장 최근 행”을 같은 거래일 데이터로 간주해서는 안 된다는 사실이 확인됐다.

처리 방침:

- 모든 원천에 `source_trade_date`, `observed_at`, `age`, `stale`을 저장한다.
- 엔진 실행 전 원천 거래일 일치 검사를 수행한다.
- 휴장일·장 마감 후에는 목표 거래일과 다른 원천을 자동으로 혼합하지 않는다.

## 4. 장중 검증 대기 항목

2026-08-01이 토요일이므로 다음 항목은 실제 호출하지 않고 `PENDING_MARKET_SESSION`으로 유지했다.

| 항목 | 확인할 내용 |
|---|---|
| KIS `H0UPPGM0` | 프로그램 누적값·단위·패킷 시각 |
| KIS `H0STCNT0` | `CCLD_DVSN` 값 의미, 누적 매수·매도 필드, 체결 시각 |
| KIS `H0STASP0` | 호가 패킷 시각, 체결 스트림과 도착 순서 |
| 키움 `ka90005` | 현재 거래일 프로그램·베이시스와 마감 시각 행 |

## 5. 호출 금지 유지 항목

`kiwoom_market_breadth`는 공식 REST 요청 경로·본문·응답 필드가 확인되지 않아 실행 불가 상태로 유지한다. `ka20001/OPT20001`이라는 명칭만으로 신규 REST 호출을 만들지 않는다.
